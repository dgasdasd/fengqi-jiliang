# 风栖过的脊梁
## 台风主题交互 H5 —— 第一页「封面」 + 第二页「台风眼」

---

## 一、怎么打开

**双击 `index.html` 即可**（纯原生 HTML / CSS / JavaScript，**无需服务器、无需联网、无构建**）。

```bash
python -m http.server 8899 --directory .
# 打开 http://127.0.0.1:8899/
```

舞台恒为 **448 : 960**（竖版手机比例），窗口比它高时上下留纸色、比它"矮"时左右留纸色，
任何尺寸下构图都不变形。桌面浏览器（≥600px）自动变成一台居中的手机框预览。
推荐 Chrome / Edge（SVG `mask` + `filter`、`mix-blend-mode`、`backdrop-filter`）。

## 二、这两页做了什么

### 第一页 · 封面《风栖过的脊梁》

**出场顺序：① 山 → ② 台风图标自左向右过山川 → ③ 题目和人。**

| 时刻 | 动作 |
| --- | --- |
| 0.20s | 雾起，黑色山影自下方浮起（`multiply` 融进纸面），山脚同时撒出一层墨点飞白 |
| 1.20s | **水墨台风出现在"山的右肩上方"**，一边旋转一边向右上抬起飘走，边飘边缩小 |
| 3.40s | 台风淡出，画面上不留任何痕 |
| 3.40s | **人影由小放大出场**：0.35 倍 → 原大，支点在脚上（人往上长），同步淡入，1.15s 完成 |
| 3.60s | **题字整块淡入**（1.9s 完成）。人比题字早 0.2s 起、早 0.9s 收 —— 原片就是这个错开 |
| 5.60s | 副题淡入（右下） |
| 6.20s | 「向下滑动」提示出现 |

> 台风的位置与动向是按原片量的：开场第 1 帧它的中心在**画面宽 82%、高 35%**处，
> 也就是山的右肩上方；随后旋转、缩小、向右上淡出，几帧之内就没了。
> 它**不横穿整座山**，**也不留任何痕**——飘走就是飘走。
> 最后一屏只有山、人和题，与原片一致。

**题目的排布与用色是照着原片量的**，不是自己编的。原片里六个字是三对错落的阶梯——
每对的第一个字高、第二个字低且右移，一路向右下行进；并且**只有「风」是灰色**，
「栖过的」是墨色，「脊梁」是朱砂：

| 字 | left | top | 字号 | 颜色 |
| --- | --- | --- | --- | --- |
| 风 | 6% | 8.8% | 86 | 灰 `--ink-faint` |
| 栖 | 20.5% | 17.4% | 92 | 墨 |
| 过 | 36.2% | 8.8% | 86 | 墨 |
| 的 | 49.5% | 16.9% | 92 | 墨 |
| 脊 | 64% | 9.1% | 100 | 朱砂 |
| 梁 | 76% | 17.1% | 100 | 朱砂 |

（位置取自对参照帧做连通域分析后的字心坐标，字号按字面尺寸换算到 448×960 舞台。）

风痕不是一条等宽线：它是一笔**有粗细变化的墨**（见第四节），逐段显影，
像毛笔真的从山川上扫过去。

### 第二页 · 台风眼

**与原片同一套结构：定屏，内容全部留在画面上，靠底部提示进入下一页。**

整屏交给那幅海浪油画。滑到这一页后按秒表依次出现，**时刻照原片一帧帧量出**，
写在各自的 `data-t` 上：

| 元素 | 出现时刻 | 原片对应 |
| --- | --- | --- |
| 超强台风 登陆沿海多地 | 0.5s | t=4.0s |
| 城乡紧急 人员转移 | 2.0s | t=5.5s |
| 城市内涝 道路积水严重 | 2.5s | t=6.0s |
| 多方力量 奔赴救灾一线 | 3.0s | t=6.5s |
| 风起沧海 / 岁岁设防 | 4.2s（渐显到 5.0s） | t=7.5→8.5s |
| ~~点击屏幕，解锁完整台风故事~~ | — | 按需求已删除这行文案 |

注意**大字标语是最后出现的**（原片里它在四条新闻之后才推上来）。
**所有文字出现后就停在画面上，不会消失。**

**出现方式**：原片里每一条是**"从上方滑下来落位"**的 —— 先在上方若隐若现
（模糊 + 半透明），再往下滑到最终位置并变清晰。逐帧量出的滑动距离各不相同：

| 行 | 起点 y | 落定 y | 滑动距离 |
| --- | --- | --- | --- |
| 超强台风 | — | 166 | 40 |
| 城乡紧急 | 202 (t=5.5) | 244 | 46 |
| 城市内涝 | 560 (t=6.4) | 684 | **118** |
| 多方力量 | 590 (t=6.7) | 756 | **158** |

关键是**上一行还没落定，下一行就已经在上面若隐若现**（原片里 t=6.7 时
城市内涝和多方力量同时在场、且靠得很近，之后一起往下落、逐渐拉开）。
所以每条各给一个 `--dy`（滑动距离）和一个 `data-t`（开始下落的时刻），
过渡是 **`transform 1.15s` + `opacity .75s` + `filter .75s`（都是 ease-out）**。

**透明度要收得比位移快**：原片是"先看清、再慢慢落位"，
不是"落到位了才看清"。反过来的话会显得拖沓。

**模糊只能给一点点**（`blur(3u)`）：原片里字一出来就是**基本清晰的**，只是淡。
给大模糊（试过 8u）会变成"从雾里浮出来"，和原片完全不是一回事。

大字标语的模糊时长给到 0.95s。

**红白配色**（扫原片红字位置对照文案长度得出，容易搞反）：

| 行 | 红 | 白 |
| --- | --- | --- |
| 超强台风 / 登陆沿海多地 | 超强台风 | 登陆沿海多地 |
| 城乡紧急 / 人员转移 | 人员转移 | 城乡紧急 |
| 城市内涝 / 道路积水严重 | 城市内涝 | 道路积水严重 |
| 多方力量 / 奔赴救灾一线 | 多方力量 | 奔赴救灾一线 |

字号与位置同样按原片实测（原片这一页正好也是 448×960，1:1 对得上）：

| 元素 | 原片 | 取值 |
| --- | --- | --- |
| 四条新闻 | 10 字跨 293px → 约 30px | `30 * var(--u)` |
| 风 / 防 | 高 148px、宽 197px | 74px × **2.0em**（=148px） |
| 起沧海 / 岁岁设 | 约 74px | 74px |

标语**两行都居中**（原片第一行 x 22→430，页宽 448，中心 226 ≈ 页面中心 224），
行距按原片实测 **2.02**（风 的顶 300 到 防 的顶 452 相距 152px ÷ 74px），
整块下移到 `top:31.6%`。
| 点击屏幕… | 13 字跨 320px → 约 25px | `25 * var(--u)` |

**交互**：文案和扩散圆环都已按需求删除，第二页**没有任何可见的交互元素**。
但热区仍在：`.cta{inset:0}` 是一个**透明的整屏点击区**，
点屏幕任意位置都能进下一页（按下时不显示任何东西）。

点底部提示 → 画面上的文字**沿到风眼中心的极坐标被吸进去**（半径收缩 + 角度旋转 +
缩放 + 淡出，1.2s），随后滑到第三页。——吸入从"滚动驱动"改成了"点击触发的转场"，
这样文案才能像原片那样一直留在屏上。

## 三、设计系统

`css/tokens.css` 是全站唯一变量来源，页面只引用变量。

- **色**：宣纸 `#f3f3f1` / 墨 `#0d0d12` / **朱砂 `#c8362f` 是唯一强调色**。
  第一页亮、第二页交给素材的深蓝，中间靠滚动完成昼夜转场。
- **字**：
  - **第一页题字不用字体，直接用原片的字形**。原片用的是一套更重的手书体（不是马善政，
    马善政只有 Regular 一个字重，加描边会把**笔锋**——起收笔的尖和顿——糊平）。
    做法见第四节"题字是抠出来的"。
  - 第二页的「风起沧海 / 岁岁设防」和底部提示仍用 **Ma Shan Zheng** 子集（48 字，18.3 KB），
    红字用 `-webkit-text-stroke` 加重。
- **形状锁**：全站方形（`--r:0`），只有 CTA 用胶囊。
- **单位**：`--u = 舞台宽 / 448`，所有尺寸写成 `calc(N * var(--u))`，
  整套排版随舞台等比缩放，不用写断点。
- **层级**：`--z-scene / --z-title / --z-ui / --z-progress` 四层，没有魔法数字。
- **动效**：一律只动 `transform / opacity`；`prefers-reduced-motion` 下全站静态呈现
  （台风图标隐藏、风痕直接给出最终形态）。

## 四、技术实现要点

### 1. 几何不是估的，是从素材图里量出来的

用 Python + Pillow 逐列扫描山图（842×1190）：

- 每列**最高非白像素** → 21 点后层山脊 `RIDGE`
- 每列**最高 lum<60 像素** → 21 点**黑山轮廓** `FRONT` —— 画面上真正看到的"山川"就是这一层

于是：

- **台风航线** = 黑山轮廓整体上移 46px（≈ 台风图标半高，刚好不压山）
- **人影落点** = 头顶不得越过山脚：`max(山脚 + 8, 底边 − 430)`
- **山体位置** = 让黑山块下沿落在 `MOUNT_BASE = 515`，山脚再往下由遮罩化成雾
- **风眼坐标** = 对海浪图取 lum<34 像素质心 → `(0.45, 0.48)`，
  吸入终点和 CTA 位置都由它算出来

### 2. 山脚化雾用的是 SVG 遮罩，不是 CSS 遮罩

一开始用 CSS `mask-image` 让山脚淡出，结果在图框底边（y=530）被切出一条硬边——
SVG 子元素的 CSS 遮罩参考框不可靠。改成在 SVG 用户坐标里放一个
`<mask>` + `<linearGradient>`（y 从 452 淡到 514，图框底在 515），
淡出在碰到图框前就已经到 0。

> 实测确认：沿列采样亮度，451→515 是 0→243 的平滑过渡，没有硬边。

### 3. 台风的航线只是一条隐形的定位线

台风划走的那段短弧做成 Catmull-Rom → 三次贝塞尔的平滑路径，挂在一条
`fill:none; stroke:none` 的 `<path id="flyPath">` 上，只用来 `getPointAtLength()` 取点。
台风本体沿它平移 + 旋转 + 缩小（1 → 0.42），透明度在最后 28% 淡出——
**画面上不画线、不留痕**。

### 3.4 整屏翻页（scroll-snap）

三页各占一屏，**一次滑动只翻一页**，不会一路滑到底：

```css
html{ scroll-snap-type:y mandatory; overflow-y:scroll; }
.sec{ height:100svh; scroll-snap-align:start; scroll-snap-stop:always;
      display:grid; place-items:center; }
```

- `mandatory` = 松手一定吸附到最近的页边界
- `scroll-snap-stop:always` = 快速划也只翻一页，不会连翻
- `.sec` 用 grid 居中，舞台（`--sh`）比屏幕矮时上下留白，不会露出下一页的半截

> **踩过的坑**：`body{overflow-x:hidden}` 会**直接废掉 scroll-snap**。
> 因为它让 body 变成滚动容器，html 上的 `scroll-snap-type` 就不生效了。
> 必须改用 `overflow-x:clip`（同样裁横向溢出，但不创建滚动容器）。
> 定位方法：写一个最小对照页二分——把 section 直接放 body 下吸附正常，
> 一旦加上 `body{overflow-x:hidden}` 就失效。

## 3.5 线上部署与"慢网"处理

线上地址：**https://dgasdasd.github.io/fengqi-jiliang/**（GitHub Pages，免费长期）

国内访问 GitHub Pages 延迟高，实测每个资源要 **600~1400ms**（本地是 15ms），
所以做了三件事：

1. **压包体**：图片从 603KB 降到 351KB
   - `bg-eye.webp` 201→134KB（q72）
   - `bg-smoke.jpg` 160KB → `bg-smoke.webp` **8.8KB**（q74，画质实测平均差 0.93、P99=4，肉眼无差）
   - `typhoon-ink.webp` 51→37KB、`person.webp` 48→43KB、六个题字共 119→103KB
   - 整页传输 **641KB → 402KB**

2. **预加载关键资源**：`<link rel="preload">` 预热雾底、漩涡、人影、字体

3. **慢网保护**：第二页的动画**先等 `bg-eye.webp` 加载完再念秒表**（`whenImagesReady`，最多等 8 秒）。
   否则动画会在背景还没出来时就开始跑，看着就是"字先蹦、图后蹦"，像坏了。

> 改完要重新验证画质：逐像素对比过新旧版本，第一页平均差 0.02（等于完全一致）。

## 4. 题字是抠出来的，不是排出来的

原片里的题字被微信的两个悬浮图标压住了一部分（图标在屏幕上固定不动，内容会滚动）。
于是做了**多帧合成**：

1. 从原片 2.52s 起按 30fps 取 14 帧（这一页正在滚走）
2. 用**行亮度签名**估每帧的滚动偏移 → `0, 21, 87, 119, 122, 125, 128, 131, 133`
3. 把每帧按偏移映回第一页坐标，**被图标盖住的像素就从别的帧取**
   —— 图标的位置在所有帧里是一样的，但内容相对它在移动，于是每块像素总能找到一帧是露出来的
4. 得到一张干净的题字（`_work/title_clean.png`），再按字形抠成 6 张透明 WebP

抠图时的三个要点：

- **用连通域给每个字分配像素**：六个字的框有重叠（脊 的框和 的 的框在
  x 295-323 / y 240-257 相交），按矩形裁会把邻字的笔画带进来（的 上面就多了一点红）。
  改成先做连通域标记，**每个墨迹像素只归属一个部件**，再按归属抠，彻底不串味。

- **红字用绿通道取 alpha**：红墨的绿通道接近黑（58），灰的绿通道接近白（200），
  用绿通道算 alpha，残留的图标灰会被自然滤掉。黑字用亮度通道即可。
- alpha 加 0.14 的下限再重映射，去掉边缘那圈几乎看不见的底灰。

六张图按**原片像素坐标** 1:1 落位（`--x / --y / --w / --h` 直接就是原片里的 bbox），
所以是真正的复刻，不是"接近"。

**一处已知限制**：微信那两个悬浮按钮（星标、刷新）在屏幕上固定不动，而滚动最多只到 137px，
所以「梁」右侧约 18% 的像素在**所有帧里都被压着**，视频里取不到。
关键点：**悬浮按钮固定在屏幕上，而内容在滚动** —— 同一块像素在不同帧里被挡的位置不同。
所以对 梁 的每个像素，在**全部 12 个偏移的帧里挑最好的那一帧**：

对 梁 的每个像素，在**全部 12 个偏移的帧**里算出 alpha，**取最大值**：

- 该帧没被挡 → 直接用原片像素，记下 alpha
- 该帧在按钮的**半透明**圆盘下 → 除以实测系数 0.597 反解，再算 alpha（按钮是**压暗**不是盖死）
- 该帧被白色星形/刷新图标盖住（亮度 > 205）→ 这一帧不算数，跳过

**取最大值**而不是"取第一个可用的"是关键：滚动中的帧有运动模糊，取第一个会取到模糊帧，
整个字就发淡。取最大值保证"只要有任何一帧显示这里是墨，就用它"。

只有**所有 12 帧都被白色图标盖死**的像素才用 Ma Shan Zheng 兜底（阈值 45 已按同字的「脊」标定）。

> 另一个坑：按钮圆盘的**左边界**要先量准。圆盘右边界 438、直径约 52 → 左边界 386。
> 一开始我按 374 掩，多掩了 12px，把 梁 左边三点水本该干净的部分也拿去做反解，噪声放大后发花。

补完还有两处要收尾：

1. **全帧都被白色图标盖住的小洞**（约 80 像素）不能用字体兜底——字体笔画偏细，会留一块淡斑。
   改用**形态学填充**：在洞内迭代取邻域最大，让周围的笔画自己长进去。
2. **反解出来的像素达不到满 alpha**（原片里被压得最狠的 x 402-422 / y 258-290 一段只有 0.5~0.9）。
   参照里 梁 和 脊 一样是**单色实心**，所以最后给 alpha 加一条对比曲线
   （≤0.28 归零、≥0.62 拉满），把笔画推成实心。

> 五个字（风栖过的脊）是**原片像素级复刻**（差分验证：笔画内部差值为 0）；
> 梁 也是原片像素，只是其中 15% 经过了半透明反解。

### 5. 素材先过一遍管线

| 素材 | 原始 | 输出 | 说明 |
| --- | --- | --- | --- |
| 山 | 50.0 KB jpg | **6.4 KB** webp | 平涂色块，webp 压缩率极高 |
| 水墨台风 | 701.9 KB png | **50.8 KB** webp | 收紧 alpha 边后缩到 512 宽 |
| 人物剪影 | 412.9 KB png | **48.0 KB** webp | 缩到高 1400（够 2x 屏） |
| 海浪漩涡 | 751.8 KB jpg | **201.3 KB** webp | 整屏底图，q84 |
| 雾 | 163.8 KB jpg | 159.9 KB | 原样保留 |

整站 494 KB，首屏实际要拉的只有约 110 KB。

### 6. 性能与无障碍

- 图片 `decoding="async"`；离屏元素不参与绘制
- 滚动主循环只在 `measureEye` 里读一次尺寸，`frame()` 内不触发重排
- 吸入进度做指数平滑（`lerp 0.16`），滚轮跳跃不闪
- 平滑跳转可被 `wheel / touchstart / keydown` 打断，不劫持滚动
- SVG 场景 `pointer-events:none`，不挡交互
- CTA 是真 `<button>`，可键盘触达

## 十、修订记录

| 问题 | 处理 |
| --- | --- |
| **整个第二页的出场都是"瞬间闪现"，没有过渡** | 根因不在动画参数，而在 `tokens.css` 少了一个变量：CSS 里写了 `var(--e-inout)`，但 tokens 只定义了 `--e-out` / `--e-emph` / `--e-in`。**`var()` 引用未定义的变量时，整条声明在计算值阶段作废** —— 不是丢掉那一段缓动，是整条 `transition` 都没了。补上变量后过渡立即恢复。教训：改完动画要用 `getComputedStyle` 逐帧读一遍实际曲线，不能只看最终截图 |
| **首页上半部分是纯白，雾底纹只在下面露出来** | 根因是 SVG 里的 `mix-blend-mode: multiply`：**SVG 内部是独立混合组**，山影素材的白不是"乘进背景"，而是**不透明地盖住**了下面的雾 —— 山影图覆盖 y −490~700，这段的雾全被挡掉。改法：把山影做成 **白=透明**（`α = 1 − 亮度`、颜色取黑，等价于手算 multiply），不再依赖混合模式。素材换成 `ridge-a.webp` |
| **人影只是原地淡入，显得假、不协调** | 原片逐帧看：人是由小放大出场的（约 0.35 倍 → 原大，约 1.1s），缩放**支点在脚上**——人往上长而不是原地膨胀。已照做，并让题字比人晚 0.2s 起、晚 0.9s 收 |
| **题字是逐字出现的** | 原片逐帧看：六个字从 t≈0.2s 起**就同时是淡的**，到 t≈2.0s 一起变实——**没有逐字**。改为整块淡入（动画加在 `.title` 上，`.c` 只负责 1:1 定位），人影与题字同一段时间淡入 |
| **题字的笔锋对不上** | 先用 `-webkit-text-stroke` 加粗，但描边会把起收笔的尖顿糊平（梁字最明显）。改为**多帧合成 + 抠字形**，第一页题字直接用原片字形，按原片坐标 1:1 落位 |
| **梁字抠出来有空洞** | 图标掩膜漏了圆盘里的白色星形，导致图标像素混进来；改成按**饱和度**识别图标（灰=图标、红=墨），并只掩完整圆盘 |
| **的 上面多了一点红** | 脊 和 的 的裁切框重叠，把 脊 的笔画带进来了。改成**按连通域归属抠图**，每个墨迹像素只属于一个部件 |
| **过 少了一点** | 过 的 辶 上那个点是**独立连通域**（185 像素），按"最大部件"抠图会漏掉。改成把**中心落在该字框内的所有部件**都收进来 |
| **梁字发虚、粗细不匀** | 对全部六个字都做了多帧合成，对齐误差造成重影；其实图标只在 x≥378，前五个字根本不碰。改为**直接从原帧抠** |
| **梁字越改越差** | 走了弯路：① 用「脊」的密度标定「梁」（两字笔画密度不同，比错了）；② 按矩形拼接（接缝成块）；③ 多帧"取第一个可用"（取到运动模糊帧，整字发淡）；④ 图标左边界按 374 掩（多掩 12px，把三点水也做了反解，发花）。**最终：逐像素在 12 帧里取 alpha 最大值**，图标边界按实测的 386 |
| **台风飘走后还留一道墨** | 整个删掉：墨迹的渐变 / 遮罩 / 滤境 / 缎带路径全部移除，航线改成一条不可见的定位线（`fill:none; stroke:none`），台风飘走就没了 |
| 底纹不统一 | 除第二页外，每页的底都是同一张雾（`bg-smoke.jpg`），上面压 42% 纸色 |
| 第二页内容会消失 | 改成定屏：四条新闻 + 大字标语 + 底部提示**全部留在画面上**，点击才触发吸入转场 |
